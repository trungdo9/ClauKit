## Consistency findings

- **Check-slug names match verbatim** between phase-08.1 and shipped code everywhere cited: `doc-on-document-kind` (:114), `out-of-scope-on-wrong-kind` (:118-119), `missing-key` (:90, generic — not per-key as one might assume from the plan's phrasing "each in the exact shape ... already use"), `missing-out-of-scope` (:117), `unparented`/`dangling` (spine-index.cjs:84,86), `parent-kind-not-allowed` (spine-index.cjs:141). No naming drift found.
- **One imprecise line-cite**: `spine-compose.cjs:138-146` (Gate 5, phase-08.1:227) should be `:139-148` (or at minimum include `:147`, the `TC` call) to cover the full enumerated kind list that the "CR cannot leak" argument rests on. Not load-bearing — the substantive claim holds regardless of the exact range — but worth a one-line fix before Gate 5 is run so a reviewer checking "the explicit kind list" at the cited lines doesn't miss `TC`.
- **`out-of-scope-on-wrong-kind` citation (`:118`) points at the `if` condition, not the `push` call (`:119`)** — inconsistent with `doc-on-document-kind` (`:114`), which is a single line containing both. Not a defect, just a citation-style asymmetry worth noting if a later phase copies this citation pattern.
- **Exports symmetry holds**: today's `spine-parse.cjs` exports only symbols consumed elsewhere (`parseEntity, DOC_ID, ITEM_ID, KIND_ORDER, DOC_KINDS, PARENT_KINDS`), leaving `CONFIDENCE`, `OUT_OF_SCOPE_KINDS`, `TOUCHES_KINDS`, `REQUIRED_KEYS` internal. 08.1's "export `CR_STATUS` only" plan follows the identical convention — no drift.
- **`traceability.cjs`'s export-by-spread mechanism (`module.exports = { main, ...spine }`, :92) is real and sufficient** for `changelog` to surface without a second edit, exactly as task 8.1.3 claims.
- **`tests/ba-spine.test.js` is already past the file's own 200-line guidance (216 lines) before any 08.1 edit**, and 08.1 adds 4 more tests to the same file (by explicit design, task 8.1.8 forbids a second spine test file) — the file will grow past 216, not shrink. Phase 08.1 is transparent about this ("re-measured here rather than quietly doubled") rather than hiding it, but the underlying guidance/reality gap is real and getting wider.
- **`REQUIRED_KEYS` currently has 6 entries** (`id, kind, project, parents, source, confidence`); `title` and `doc` are enforced by their own bespoke checks (comment at `spine-parse.cjs:36`), which is exactly the mechanism phase-08.1:60 cites as precedent for keeping `status`/`impact` out of that array too.
