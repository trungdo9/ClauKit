1. **Phase file title vs. plan.md phase number/filename.** `plans/260910-1533-ba-kit/phase-11-prior-art-scan-optional.md:1` reads `# Phase 14 — D-2 prior-art spike (1 day, timeboxed)`, but `plan.md:355` lists it as `| 11 | *(optional)* Prior-art reference scan, license-first | [phase-11-prior-art-scan-optional.md](phase-11-prior-art-scan-optional.md) | — |` and the file is itself named `phase-11-...md`. The file's own H1 disagrees with both its filename and the plan's phase table (11 vs 14). Cosmetic (task IDs inside the file, e.g. "Task 14.1", "Task 14.1b", are internally consistent with its own "14" — only the phase number/title is out of step with plan.md), but a reader following plan.md:355's link lands on a document that calls itself something else.

2. **`capability-map.md` attributed to the wrong phase.** `phase-11-prior-art-scan-optional.md:46` (task 14.2): *"Derive the names from `.claude/skills/ba/capability-map.md`'s 55-row table **(phase 06)**..."* — REFUTED against plan.md's own phase table and phase-03's own content: `plan.md:347` `| 03 | Rules + kit README + capability map (55 names, redirect rows) | phase-03-rules-readme-capability-map.md | ...`; `phase-03-rules-readme-capability-map.md:62` `## Task 3.3 — CREATE `skills/ba/capability-map.md` (D-5 item 4)`. `phase-06-ba-spec.md` contains zero occurrences of "capability-map" (`grep -n capability-map phase-06-ba-spec.md` → no output) — phase 06's own Interfaces/Produces list (lines 6-13) never mentions it. The citation should read "(phase 03)".

3. **Wave-4 "first manifest write" claim contradicts phase 01/06/08's own present-tense description.** `plan.md:407` (Wave 4, `export`): *"The first `ba` command needing `requires.shared`... Note that `/ba:spec tc`'s dependency on the `scenario` skill (phase 08 task 8.3) is the first such entry chronologically, even though `export` is where **the manifest field first gets written**."* This says the `requires.shared` key in `ba.json` is not literally written until wave 4. But: `plan.md:91` (Global Constraints, Identity table) lists `requires.shared` as **exactly three** entries with no wave qualifier, alongside `Manifest | .claude/kits/ba.json` (phase 01, wave 0); `plan.md:326` (Architecture diagram, wave-0 section) shows `requires.shared: scenario/SKILL.md + ... ──▶ (three engineer files, link-clean)` as part of the wave-0 architecture; `phase-06-ba-spec.md:28` states *"`scenario/SKILL.md` is a `requires.shared` entry in `ba.json` (**phase 01**)"* — present tense, phase 01 = wave 0; `phase-08-qc-gap-and-handoff.md:57` independently states *"`ba.json` ships [scenario/SKILL.md] via `requires.shared` (**phase 01**)"*. Four wave-0 citations (Global Constraints, Architecture, phase 06, phase 08) all say the `requires.shared` field with the scenario entry is already in `ba.json` at phase 01/wave 0, against one wave-4 sentence claiming that field is "first written" at export. The wave-4 sentence's own hedge ("even though...") shows the plan is aware of the tension but does not resolve which is true — is `requires.shared` in the wave-0 manifest (three entries, per Global Constraints) or does it first appear at wave 4 (per the Wave-4 paragraph)? As written, both cannot be literally true of the same field.
